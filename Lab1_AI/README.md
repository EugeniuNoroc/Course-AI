## 1. Постановка задачи

Нужно написать программу на Java, которая проверяет, принадлежит ли введённое слово языку:

```
(abcd)ⁿ (ef)ᵐ,   n ≥ 1,  m ≥ 1
```

Простыми словами: сначала идёт **один или больше** блоков `abcd`, а потом **один или больше** блоков `ef`. Порядок строгий — сначала все `abcd`, потом все `ef`. Менять их местами нельзя.

Примеры правильных слов: `abcdef`, `abcdabcdef`, `abcdefef`.
Примеры неправильных: `ef` (нет `abcd`), `abcd` (нет `ef`), `abcdefabcd` (после `ef` снова `abcd`).

---

## 2. Диаграмма автомата

![Диаграмма ДКА](dfa_diagram.png)

Здесь:

- `q0` — стартовое состояние;
- `q1, q2, q3, q4` — набор `a → b → c → d` (чтение одного блока `abcd`);
- стрелка `a` из `q4` обратно в `q1` — позволяет прочитать ещё один блок `abcd` (это и есть `n ≥ 1`);
- `q5, q6` — чтение блока `ef`;
- стрелка `e` из `q6` обратно в `q5` — позволяет прочитать ещё один блок `ef` (это и есть `m ≥ 1`);
- `q6` обведено двойным кружком — это **принимающее (конечное)** состояние.

---

## 3. Описание состояний

| Состояние | Что означает |
|-----------|--------------|
| `q0` | старт, ещё ничего не прочитано |
| `q1` | прочитан `a` |
| `q2` | прочитан `ab` |
| `q3` | прочитан `abc` |
| `q4` | прочитан `abcd` (блок закончен, можно начать новый `abcd` или перейти к `ef`) |
| `q5` | прочитан `e` (начало блока `ef`) |
| `q6` | прочитан `ef` — **принимающее состояние** |
| `TRAP` | ловушка: попался неверный символ или неверный порядок |

---

## 4. Таблица переходов

| Из состояния | Символ | В состояние |
|--------------|--------|-------------|
| q0 | a | q1 |
| q1 | b | q2 |
| q2 | c | q3 |
| q3 | d | q4 |
| q4 | a | q1 *(ещё один блок abcd)* |
| q4 | e | q5 *(переход к блокам ef)* |
| q5 | f | q6 |
| q6 | e | q5 *(ещё один блок ef)* |

Все переходы, которых нет в таблице, ведут в `TRAP`, и слово сразу отклоняется.

## 5. Пояснение кода

### Состояния и таблица переходов

Состояния я описал через `enum`, а переходы храню в `Map`, где по паре *(состояние, символ)* можно узнать следующее состояние:

```java
private enum State { q0, q1, q2, q3, q4, q5, q6, TRAP }

private static final Map<State, Map<Character, State>> TRANSITIONS = new EnumMap<>(State.class);
```

В статическом блоке `static { ... }` я сначала создаю пустую таблицу для каждого состояния, а потом добавляю нужные переходы методом `addTransition`:

```java
addTransition(State.q0, 'a', State.q1);
addTransition(State.q1, 'b', State.q2);
addTransition(State.q2, 'c', State.q3);
addTransition(State.q3, 'd', State.q4);
addTransition(State.q4, 'a', State.q1); // ещё один блок abcd
addTransition(State.q4, 'e', State.q5); // переход к блокам ef
addTransition(State.q5, 'f', State.q6);
addTransition(State.q6, 'e', State.q5); // ещё один блок ef
```

### Главный метод `accepts`

Это и есть работа автомата. Начинаем со стартового состояния и идём по строке символ за символом. Для каждого символа смотрим в таблицу, куда переходить. Если перехода нет — попадаем в `TRAP` и сразу возвращаем `false`. В конце проверяем: находимся ли мы в принимающем состоянии `q6`.

```java
public static boolean accepts(String input) {
    State current = START;                 // начинаем с q0
    for (int i = 0; i < input.length(); i++) {
        char c = input.charAt(i);
        State next = TRANSITIONS.get(current).get(c);
        current = (next != null) ? next : State.TRAP;
        if (current == State.TRAP) {
            return false;                  // неверный символ/порядок — выходим сразу
        }
    }
    return ACCEPTING.contains(current);    // true только если оказались в q6
}
```

### Главная логика (в чём «фишка»)

Самый важный момент — **переход `q4 → q5` по символу `e`**. Именно здесь автомат «понимает», что часть `abcd` закончилась окончательно и назад дороги нет. Причина простая: из состояний `q5` и `q6` **нет ни одного перехода по `a`, `b`, `c`, `d`**. Поэтому если после `ef` попробовать снова написать `abcd`, автомат уйдёт в `TRAP`. Так и отклоняется слово вроде `abcdefabcd`.

### Метод `main`

В `main` я просто прогоняю два списка слов — правильные и неправильные — и печатаю результат `true/false`. Ещё можно передать своё слово через аргумент командной строки, тогда программа проверит и его.

## 7. Инструкция по запуску в IntelliJ IDEA

1. Открыть IntelliJ IDEA → **File → New → Project**, тип проекта **Java**, выбрать JDK (например, 17 или новее), нажать **Create**.
2. В папке `src` создать пакет `org.example` (правой кнопкой по `src` → **New → Package**).
3. Внутри пакета создать класс: правой кнопкой по пакету → **New → Java Class**, назвать его так же, как класс в коде (`DFA`), и вставить код программы.
4. Убедиться, что первая строка файла — `package org.example;`.
5. Запустить: нажать на зелёный треугольник ▶ слева от метода `main` (или **Shift + F10**).
6. Результат появится в окне **Run** внизу.

**Чтобы проверить своё слово** через аргумент командной строки:

1. Сверху нажать на имя конфигурации → **Edit Configurations…**
2. В поле **Program arguments** написать своё слово, например `abcdabcdef`.
3. Нажать **OK** и запустить программу заново — внизу появится строка с проверкой этого слова.
