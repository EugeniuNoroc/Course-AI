# Лабораторная работа: мини-макс с альфа-бета отсечением

**Вариант 4:** глубина дерева — 6, ширина — 3, в дереве есть отрицательные значения.
**Язык:** Java. **Файл:** `AlphaBetaVariant4.java`

## 1. Цель

Реализовать рекурсивный мини-макс с альфа-бета отсечением и сравнить его с обычным мини-максом по числу проверенных узлов и времени работы.

## 2. Идея алгоритма

Два игрока ходят по очереди. **MAX** (мы) стремится получить наибольший результат, **MIN** (противник) — наименьший. Дерево содержит все варианты партии: корень — текущая позиция, листья — итоговые оценки. Уровни чередуются: 0 — MAX, 1 — MIN, 2 — MAX и так далее.

**Мини-макс** считает все узлы. В узле MAX берётся максимум из значений детей, в узле MIN — минимум. Предполагается, что противник всегда отвечает лучшим для себя ходом.

**Альфа-бета** даёт тот же ответ, но не проверяет ветки, которые не могут повлиять на выбор.

> **α** — сколько мы уже гарантировали себе в проверенных ветках.
> **β** — до скольки враг может нас опустить в текущей ветке.
> Если **α ≥ β**, текущая ветка не лучше того, что у нас уже есть: либо враг нас сюда не пустит, либо мы сами сюда не пойдём. Остальных потомков не проверяем.

| Где срабатывает `break` | Что произошло | Кто отказывается от ветки |
|---|---|---|
| узел MAX | α выросла до β | MIN не пустит нас сюда |
| узел MIN | β упала до α | MAX сам сюда не пойдёт |

Обход идёт **в глубину, слева направо**, поэтому α и β успевают накопиться в первых ветках и дают отсекать следующие. Первый вызов: `alphaBeta(root, −∞, +∞, MAX)`. Начинать нужно именно с ±∞, а не с 0, иначе на отрицательных значениях ответ будет неверным.

## 3. Логика кода

| Элемент | Назначение |
|---|---|
| `Node` | узел дерева: уровень, значение, список детей |
| `buildRandomTree` | рекурсивно строит полное дерево: 3⁶ = 729 листьев, 1093 узла; листья — случайные целые |
| `minimax(node, isMax)` | полный перебор всех узлов |
| `alphaBeta(node, α, β, isMax)` | рекурсивный поиск с отсечениями |
| `Stats` | счётчики: проверенные узлы, листья, отсечения, посещения по уровням |
| `experiment`, `averageOverTrees` | сравнение алгоритмов и усреднение по 200 случайным деревьям |

Ядро алгоритма (ветка MAX, ветка MIN устроена зеркально):

```java
int best = Integer.MIN_VALUE;
for (Node child : node.children) {
    int v = alphaBeta(child, alpha, beta, false, s); // ход переходит к MIN
    best = Math.max(best, v);                        // лучший найденный вариант
    alpha = Math.max(alpha, best);                   // MAX улучшает гарантию
    if (alpha >= beta) {                             // MIN сюда не пустит
        s.cutoffs++;
        break;                                       // отсечение
    }
}
return best;
```

В ветке MIN используются `min`, `beta = Math.min(beta, best)` и то же условие `alpha >= beta`.

## 4. Учебный пример (глубина 3, ширина 3)

![Учебное дерево с отсечениями](images/diagram_tree.png)

1. **Левая ветка.** Узлы MAX дают 5, 4 и 6, MIN выбирает минимум — 4. У корня теперь α = 4. Внутри ветки было отсечение: при β = 4 третий узел MAX нашёл 6 ≥ 4, лист −1 не проверяется, потому что MIN сюда не пустит.
2. **Средняя ветка.** MIN получает 7. У корня теперь α = 7. Внутри ветки тоже было отсечение: при β = 7 узел MAX нашёл 9, листья −5 и 3 не проверяются.
3. **Правая ветка.** Первый узел MAX дал 2, значит, β = 2. Проверяем условие: 7 ≥ 2, отсекаются два поддерева. Даже если в них большие числа, выбирает там MIN, а он нас сведёт к 2 или меньше. Мы сами туда не пойдём.

**Итог:** оценка корня 7 у обоих алгоритмов. Мини-макс проверил 40 узлов, альфа-бета — 29 (3 отсечения).

## 5. Результаты (глубина 6, ширина 3)

Дерево с листьями из [−100, 100]:

| Алгоритм | Оценка | Узлов | Листьев | Отсечений | Время, мкс |
|---|---|---|---|---|---|
| Мини-макс | −29 | 1093 | 729 | — | 7.70 |
| Альфа-бета | −29 | 287 (26%) | 161 | 70 | 1.75 |

![Узлы по уровням](images/diagram_levels.png)

Основная экономия приходится на нижние уровни: чем глубже уровень, тем больше узлов лежит в отсечённых ветках.

### Влияние отрицательных значений (среднее по 200 деревьям)

| Листья | Мини-макс | Альфа-бета | Отсечений | Доля узлов |
|---|---|---|---|---|
| [0, 100] | 1093 | 432.9 | 100.1 | 39.6% |
| [−100, 100] | 1093 | 427.9 | 98.0 | 39.1% |
| [−100, −1] | 1093 | 427.8 | 98.1 | 39.1% |

Знак значений на эффективность не влияет: алгоритм только сравнивает числа, поэтому важен их порядок.
Начальные значения α и β влияют: на дереве из отрицательных листьев запуск с α = 0 даёт −3 вместо правильного −68.

## 6. Выводы

1. Альфа-бета всегда даёт тот же результат, что и мини-макс. Это проверено на всех деревьях.
2. На дереве варианта 4 альфа-бета проверяет в среднем около 39% узлов и работает примерно в 2–4 раза быстрее. Время зависит от компьютера, а число узлов и отсечений воспроизводится, потому что seed генератора фиксирован.
3. Отрицательные значения не меняют число отсечений, но требуют начинать с α = −∞ и β = +∞.
4. Эффективность отсечения зависит от порядка обхода детей: чем раньше найден сильный ход, тем больше отсечений.
